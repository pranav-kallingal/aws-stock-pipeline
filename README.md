# End-to-End AWS Serverless Data Pipeline

## Architecture Overview
This project implements a fully serverless, cloud-native Data Engineering pipeline on AWS using the Medallion Architecture (Bronze, Silver, Gold). It automatically extracts daily stock market data from the Alpha Vantage API, processes it using distributed Apache Spark clusters, and creates analytics-ready aggregated tables.

## 🛠️ Tech Stack
* **Extraction:** AWS Lambda (Python, `urllib`, `boto3`)
* **Storage:** Amazon S3 (Data Lake)
* **Processing:** AWS Glue (Serverless PySpark)
* **Orchestration:** AWS Step Functions & Amazon EventBridge
* **Querying:** Amazon Athena (Presto SQL)

## 📊 The Medallion Architecture Flow
1. **EventBridge Scheduler:** Triggers the pipeline automatically every day at 6:00 PM.
2. **AWS Lambda (Ingestion):** Calls the Alpha Vantage REST API, parses the deeply nested JSON, flattens it into row-based records, and saves it to the `s3://landing/` zone.
3. **AWS Glue (Bronze Layer):** Reads the flattened JSON using PySpark, adds ingestion timestamps, and writes highly compressed Parquet files partitioned by `symbol`.
4. **AWS Glue (Silver Layer):** Cleanses the data, casts strings to `float` data types, calculates the `daily_return_pct` business metric, and saves to the `s3://silver/` zone.
5. **AWS Glue (Gold Layer):** Aggregates the Silver data to calculate the Average Daily Return for each company over the entire time period, saving a final summarized Parquet table to `s3://gold/`.

## 🚀 Key Data Engineering Concepts Applied
* **ELT (Extract, Load, Transform):** Flattening JSON in the Extract layer (Lambda) to prevent complex un-pivoting in the Transform layer (Spark).
* **Race Condition Prevention:** Using `.sync` (Wait for task to complete) in AWS Step Functions to prevent downstream jobs from reading files before upstream jobs finish writing them.
* **Schema-on-Read:** Resolving AWS Athena `NULL` value issues by ensuring the SQL DDL perfectly matches the Parquet schema generated by PySpark.
* **Hive Partitioning:** Partitioning S3 folders by `symbol` (`symbol=AAPL/`) to optimize query scanning costs.
* **Decoupled Execution:** Using `sys.argv` (or Glue arguments) to prevent hardcoding paths, allowing the same PySpark code to run on local Mac machines or AWS Glue clusters.
